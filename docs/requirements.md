# SnapDown-Anything · MVP 需求

你是一名资深全栈工程师。请基于开源项目 **yt-dlp**，规划并开发「万能视频下载器（SnapDown-Anything）」。

**当前阶段仅输出最小 MVP 技术方案，等待人工确认后再编写代码。** 优先本地运行，架构简单、稳定、易维护，避免过度设计。

## 1. 核心功能

- 单页网站，流程：粘贴链接 → 解析信息 → 选择画质 → 排队下载 → 实时进度 → 保存到设备。
- 首批支持 **B站、抖音、YouTube** 的单个公开视频及常见分享短链接；支持从抖音分享文案提取 URL。
- 解析后展示标题、时长、可用清晰度，默认最佳画质，允许手动选择。
- 服务端使用 yt-dlp 下载、FFmpeg 无损封装合并音视频，保留原始画质，不默认转码。
- 不支持的平台直接拒绝，返回明确原因。

## 2. 网络代理策略

由后端按平台强制路由：

- **国内平台（B站、抖音）：** 必须直连，失败不切换代理。
- **国外平台（YouTube）：** 必须使用配置的 HTTP/SOCKS 代理，代理不可用则失败，禁止回退直连。
- 支持配置本机代理或服务器可访问的代理地址，需校验代理连通性。
- 解析、媒体下载、重试等所有请求均遵循相同路由策略，防止代理绕过。

## 3. 队列与限频

- 所有任务由服务端统一管理，按平台共享限频额度。
- 限频覆盖解析、下载启动及失败重试，不可通过刷新或重复提交绕过。
- 支持排队、取消、失败重试和平台冷却倒计时。
- 失败、取消任务立即清理无用临时文件；允许续传的中断任务保留有效分片。

## 4. 进度与持久化

- 后端通过 yt-dlp 进度事件获取真实数据，前端使用 **SSE（约 1 秒更新）**。
- 状态包含：等待解析、解析中、等待下载、下载中、合并中、已完成、失败、已取消、已中断。
- 展示队列位置、可计算的等待时间、阶段进度、下载大小、速度、剩余时间和错误原因。
- 总大小未知时不显示虚假百分比；分段下载避免误报整体进度。
- 合并成功且最终文件验证可用后才标记完成。
- 任务状态持久化；关闭网页不影响服务端任务，刷新或 SSE 重连可恢复状态。
- 服务重启后，将未完成任务标记为已中断，支持人工重试，具备条件时复用有效分片。
- 下载完成后提供“保存到设备”，由浏览器获取最终文件。

## 5. 前端设计

参考 **Claude.com 暖色系视觉风格**，统一页面背景、文字、按钮、卡片及状态颜色。

要求：简洁、响应式、清晰易用，不复制品牌 Logo 或专有素材。

## 6. MVP 不包含

账号、付费、批量下载、播放列表、直播、Cookies 上传、会员/付费资源、DRM 破解、复杂分布式架构。

仅处理用户有权下载的内容，遵守平台规则。
